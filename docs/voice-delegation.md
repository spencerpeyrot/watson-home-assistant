`voice/delegation.py` owns provider-independent task commitment. `DelegationTranscriptBuffer` collects transcript deltas and one client-delegation ID. It returns nothing until audio sending ends and transcript input stays quiet for its configured interval. It keeps the provider's `offset_ms` as correlation metadata; it never treats that offset as proof the transcript is complete. Empty transcript and repeated/overlapping delegation IDs do not produce a task.

`build_task_request` copies committed transcript exactly into `request_text` and the current user turn, adds server-known device/session/conversation IDs and context revision, and derives the idempotency key from device, session, and delegation identity. The P03 synthetic spike now uses this builder. `service/live_provider.py` supplies a fake-testable provider client; P09/P10 include bounded device audio relay, job submission, progress/result routing, job-specific correction/cancel clients, and optional reconnect-persistent job links. `LocalVoiceRuntime` can bind a per-session `VoiceJobCoordinator`; its injected turn-end signal calls `mark_audio_finished`, then the coordinator joins the exact transcript after the quiet interval and appends job results to Live context. `WebRtcSpeechActivity` now provides accepted speech decisions and turn-end detection, and `device.voice_client` wires endpoint to the coordinator; the candidate is source-only and uncalibrated. Production credentials and spoken correction/cancel intent resolution remain.

`voice/jobs.py` submits typed jobs, binds one active delegation to one accepted job, parses bounded SSE responses, checks event/job/session/conversation identity and contiguous sequence, and routes correction/cancel only to the linked job with stable idempotency keys. Optional `link_database_path` persists accepted job IDs, scope IDs, context revision, event cursor, and a bounded replay-ID cache in SQLite; it stores no task text. Existing databases migrate to add the replay cache. The device credential can read/events/correct/cancel jobs only when the stored job device matches its authenticated device ID. `voice/job_orchestrator.py` consumes provider-neutral voice events, waits for local VAD end plus transcript quiet before submitting, polls the correlated job, and returns bounded progress/results as commentary/thinking context. The device sends delegation-bound updates with `VoiceContextAppend`; it sends session-wide context with `VoiceSessionContextAppend`. The gateway checks active-session identity for both and additionally requires a known client delegation for delegation-bound updates. The OpenAI key stays server-side.

`run_gateway_voice_session` accepts a per-session event-handler factory, allowing the client to build `VoiceJobCoordinator` after receiving the gateway-assigned session ID. `device.voice_client` wires local VAD turn-end to `mark_audio_finished()`.

Unit evidence on 2026-10-07 covers delegation arriving before final transcript text, VAD sender completion, quiet-gap commit, exact transcript preservation, generated correlation fields, missing transcript, duplicate IDs, ignoring server-targeted tool events, SSE replay/sequence checks including conflicting replay after restart and fail-closed old-database cursors, wrong-job rejection, correction revision checks, job-specific cancellation, result append, rejection of context for unknown delegations, SQLite link/cursor/replay-ID reload and old-database migration, and atomic cursor advancement after batch validation. `device/job_notifications.py` polls device-authorized snapshots while idle, persists unseen terminal results in a separate `0600` SQLite inbox, plays a local chime, retries failed playback, and exposes pending summaries. At the next fresh session, `VoiceJobCoordinator` asks whether the user wants the result; it accepts consent only after an assistant transcript contains the spoken offer and only for the user's first complete response. An early “yes” or later unrelated “yes” cannot release details. Result details are appended only after a tightly matched affirmative, and the inbox marks included summaries when assistant transcript begins. GPT-Live has no transcript-done or output-audio-done event, so the transcript gate cannot prove the complete offer was audible and the spoken marker cannot prove complete playback. The inbox stores returned summary/artifact/source data but not the originating request text. `DeviceJobCompletionService` owns the long-lived monitor client and creates session clients against the same per-device link database. `device/voice_service.py` injects its callback into the idle runtime, creates per-session coordinators, and closes long-lived clients when runtime exits; each `VoiceJobCoordinator.close()` closes its session client.
