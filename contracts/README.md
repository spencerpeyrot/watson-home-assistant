# Shared contracts

P00 contract draft. Pydantic models are the source of truth; generated JSON Schemas live under `schemas/v1/`. Provider-specific payloads stay inside `voice/` or `orchestrator/` adapters. Requires Python 3.12 and Pydantic 2 (`pip install -r contracts/requirements.txt`).

Regenerate schemas from the repository root after installing this package's declared dependency:

```sh
python -m contracts.export_schemas
```

Validate every checked-in JSON fixture against its Pydantic model:

```sh
python -m contracts.validate_fixtures
```

## IDs and trust

- `device_id` is a stable configured device name. Gateway checks it against the authenticated device credential.
- `owner_id` comes only from gateway authentication. It is server context, never a client-supplied `TaskRequest` field.
- `conversation_id` survives reconnects; `session_id` identifies one provider connection; `turn_id` identifies one committed user request.
- `delegation_id` is opaque provider data. Gateway correlates it with finalized transcript events before creating `TaskRequest`.
- `job_id`, `action_id`, `event_id`, and `trace_id` are UUIDs generated by the application. `parent_job_id` links delegated jobs.
- `context_revision` begins at zero and increments when user corrects a request. Reject stale writes/results from older revisions.
- `sequence` starts at one and increases by one per job event. Consumers deduplicate by `(job_id, event_id)` and detect gaps by sequence.
- `idempotency_key` is server-derived from authenticated device, session, and delegation identity. Reuse same key for retries; reject duplicate submissions.
- `TaskRequest`, `JobEvent`, and `ToolResult` propagate device, conversation, session, turn, delegation, and trace IDs. Job/action/event IDs stay on their owning records. Never log secrets or raw audio by default.
- The device voice socket uses `/v1/devices/{device_id}/connect?session_id={session_id}`. It authenticates the same device credential as HTTPS, atomically claims a matching `connecting` session as `starting` before provider startup, then marks it `ready` and emits `VoiceSessionEvent(session_ready)`. `assistant_processing` marks response work start; `assistant_response_started` marks first output audio; `assistant_response_complete` marks provider output end. The device treats completion as final only after its speaker queue drains, and must not apply idle shutdown between response start and that drain. Input PCM metadata must immediately precede its binary frame; output uses `AudioOutputFrameMetadata` immediately before its binary payload. Sequences start at zero per direction and increase by one. `VoiceContextAppend` sends bounded commentary/thinking for a client delegation already observed in that session. New `VoiceSessionContextAppend` sends bounded commentary/thinking/instructions authorized by the active session identity. Provider keys never leave the server. These P09/P10 messages remain draft until P00 review.
- The device commits each VAD-delimited turn with `AudioTurnEnd`, including its final frame sequence and total VAD-accepted speech time. The gateway forwards that duration for per-turn diagnostics and a guarded one-time repeat prompt; it does not retain audio.
- `assistant_response_complete.reply_expectation` optionally tells the Pi whether Cube expects an open answer, a yes/no confirmation, no answer, or is closing. Missing values keep the configured idle window. `assistant_turn_ignored` tells the Pi to restore the post-playback deadline after an ignored transcript without closing the session.
- The device event socket uses `/v1/devices/{device_id}/events` with the same device credential. It sends timer-fired events and correlated `LocalToolRequest`s. The device persists timer IDs/results before replying with `TimerEventAck` or `ToolResult`; an interrupted action is not re-executed automatically. The route is implemented; no worker/model action path currently dispatches `LocalToolRequest`.

## Message rules

- `TaskRequest` contains finalized task text and committed context only. Incomplete transcripts cannot authorize writes.
- `JobEvent` is append-only. Persist status, progress, correction acknowledgement, approval, artifact, and result events.
- `TimerFiredEvent.event_id` equals stable `timer_id`; delivery consumers deduplicate repeats by `event_id` after worker lease recovery.
- Timer delivery is at-least-once across transport failures; receiving device must persist/deduplicate `event_id` before presenting a reminder.
- `ToolResult.status == "needs_reconciliation"` means write outcome is uncertain; inspect external state before retry.
- `ToolResult.status == "succeeded"` is not a user-facing success claim unless `verified` is true.
- Timestamps are timezone-aware. Usage keeps token, connected-second, and USD values distinct; estimated cost labels itself.
- Cross-field rules enforced by the Python models: `cost_usd` and `cost_kind` appear together; `MemoryRecord.updated_at` is not earlier than `created_at`; `LocalToolRequest.expires_at` is later than `issued_at`; `VoiceSessionEvent` fields match its event type; output PCM payload size is even; context append content fits 500 UTF-8 bytes and must match the active session, plus a known client delegation for `VoiceContextAppend`. JSON Schema v1 captures field shape but not all relational rules, so other-language consumers must enforce them too.
- Additive optional fields may be added within a version. Changes to meaning, required fields, enum behavior, or serialization require a new `schema_version` and compatibility review.

## Module boundaries

| Module | Owns | Shared boundary |
|---|---|---|
| `contracts/` | Schemas, fixtures, identifiers, error codes | Only shared typed messages |
| `device/` | Audio, wake, mute, shutdown, emulator | Device events and local-tool transport |
| `voice/` | Live lifecycle, transcript assembly, provider events | `TaskRequest`, session/device contracts |
| `orchestrator/` | Routing, model adapters, jobs, memory | `TaskRequest`, `JobEvent`, `ToolResult` |
| `tools/` | Typed integrations, policy, action ledger | Tool request/result contracts |
| `skills/` | Research, home control, planning instructions | Orchestrator-owned inputs and outputs |
| `service/` | Gateway, auth, API, dashboard, persistence | HTTP and job-event contracts |
| `evals/` | Replay, acceptance and performance evaluation | Versioned fixtures; no provider secrets |
| `deploy/` | Cloud/Pi install, migrations, rollback | Config and operational interfaces |

## API surface draft

Gateway owns authenticated routes for session create/list/close; job submit/list/read/update/cancel; approval list/decision; memory read/write/delete; artifact fetch; usage and health. Implemented device sockets cover voice audio/session events/delegation and session context append (`/connect`) and timer/local-tool delivery with correlated responses (`/events`). Health and playback-meter messages remain contract targets; no transport carries them yet. Dashboard uses owner routes and owner-scoped SSE. Route shapes and error codes remain draft until P00/P06 review.

Run an isolated fixture host per workstream; standard library only:

```sh
python -m contracts.mock_server --profile voice --port 8765
python -m contracts.mock_server --profile device --port 8766
```

Read `GET /_mock/fixtures` for that profile's allowlist, `GET /_mock/fixtures/{filename}` for one payload, and `GET /_mock/schemas/{ModelName}` for its schema. `GET /healthz` reports mock readiness. Bind stays on loopback by default. These hosts serve deterministic fixtures; the authenticated API and device WebSocket mock lives in [`docs/service-mock.md`](../docs/service-mock.md).
